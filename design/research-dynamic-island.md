# 灵动岛调研报告（iPhone / Mac）

> 调研日期：2026-08-10
> 用途：为 DevNexus 桌面灵动岛重构提供设计依据（尺寸 / 动画 / 交互 / 功能 / 适配建议）

---

## 1. iPhone 灵动岛（Dynamic Island）官方规范

### 1.1 尺寸（单位：pt，逻辑点）

| 展现类型 | iPhone 14 Pro（393×852） | iPhone 14 Pro Max（430×932） |
|---|---|---|
| 紧凑 / 最小视图宽度 | 230 | 250 |
| 展开视图宽度 | 371 | 408 |
| 圆角半径 | **44** | **44**（与 TrueDepth 相机形状匹配） |

Live Activity 各形态尺寸（Apple 官方表格）：

| 屏幕尺寸（纵向） | Compact leading | Compact trailing | Minimal（直径） | Expanded（高度区间） | Lock Screen |
|---|---|---|---|---|---|
| 430×932 | 62.33×36.67 | 62.33×36.67 | 36.67 | 408×**84–160** | 408×160 |
| 393×852 | 52.33×36.67 | 52.33×36.67 | 36.67 | 371×**84–160** | 371×160 |

要点：
- 紧凑态是**左右两段**（相机两侧各一段），不是一整条
- 展开态高度有区间 84–160pt，**避免取区间中间的"边缘高度"**（视觉上模棱两可）
- Minimal 是圆形/椭圆，直径 36.67pt
- 内容要"同心嵌套"（concentric）：内层形状与外框等距，视觉重心贴合内壁

### 1.2 三种视图状态

| 状态 | 触发条件 | 内容 |
|---|---|---|
| **Compact（紧凑）** | 只有一个 Live Activity 活动时 | leading + trailing 两段，各自显示图标/短信息 |
| **Minimal（最小）** | 两个及以上活动同时存在 | 一个附着在岛上、一个分离显示（圆形/椭圆） |
| **Expanded（展开）** | 长按 / 重要更新自动弹出（来电、Face ID 失败等） | 分 leading / trailing / center / bottom 四个区域，可放富内容 |

### 1.3 动画细节

- **弹簧物理**：苹果用 Core Animation `CASpringAnimation` 实现"生物弹性"，故意做一点过冲再回弹，与硬件的固定形态形成对比
- 常用参数（社区复刻总结）：
  - `stiffness`（刚度）≈ **300–500**（Framer Motion 复刻用 400）
  - `damping`（阻尼）≈ **0.8–0.9**（subtlety）；复刻项目常用 30（Framer 的 damping）
  - `mass` 低（≈1.0）
  - 时长自动推导 **~0.3–0.5s**，60fps
  - iOS 18 手电筒展开：0–0.3s 缩放、0.1–0.4s 透明度、动画总时长 <1s
- **Live Activity 动画上限 2 秒**；Always-On 低亮度屏不执行动画
- 形态变化三阶段：缩放（scale）→ 透明度（opacity）→ 内容切换；用 `will-change` 预光栅化保流畅
- **Squircle（超椭圆）**：普通 border-radius 恒定曲率在末端会"突然变尖"，苹果用渐变更自然的超椭圆；复刻时先动 borderRadius 动画、结束瞬间切 clipPath
- 关键设计语言：**"像活的生物体"**——弹性（elasticity）、挤压（squish）、抖动（shake）等微动画让岛"活着"

### 1.4 交互手势

| 手势 | 行为 |
|---|---|
| **点按（tap）** | 打开对应 App |
| **长按（touch & hold）** | 展开为 Expanded 视图（iOS 18 起也可 0.5s 长按强开） |
| **从中心向左/右滑** | 展开活动看更多细节 |
| **从左右滑向中心** | 收起活动（变回紧凑/最小） |
| **左右滑切换** | 在两个活动之间切换 |
| 滑动时锁定展开态 | 防止误收起，精度提升 |

### 1.5 功能清单（系统级）

- **Live Activities**（核心第三方用途）：打车、外卖、体育比分、计时器、健身、航班
- **音频**：音乐 / 播客 / 有声书 / AirPods 电量 / AirPlay 设备（Now Playing）
- **通话**：电话、FaceTime、CallKit VoIP（WhatsApp/Zoom）通话计时
- **系统指示**：Face ID / Touch ID 提示、AirDrop、充电、屏幕录制、定位使用、麦克风使用、个人热点
- **计时器 / 闹钟**：iOS 计时器或闹钟，带快速暂停控件
- **专注模式**状态切换也会显示

### 1.6 生命周期限制

- 单个 Live Activity 最长存活 **8 小时**，到期系统自动移除
- 锁屏可再保留最多 4 小时（合计 12 小时上限）
- 最多**同时显示 2 个**活动（最小视图）
- 没有"关闭灵动岛"的总开关，只能逐 App 关闭或滑动收合

## 2. Mac 生态：官方 + 第三方

### 2.1 苹果官方

- macOS **没有内置灵动岛**；MacBook 的刘海（Notch）是硬件挖孔 + 菜单栏遮罩
- Apple HIG 对 macOS 的刘海处理：菜单栏项目自动避让凹口区域，无交互式扩展
- macOS 有原生 **Now Playing（媒体键）**、**HUD（音量/亮度）**、**AirDrop**、**实时活动在锁屏** 等分散能力，但无统一"岛"容器

### 2.2 第三方灵动岛应用对比（核心参考）

| 应用 | 价格 | 最低 macOS | 架构 | 核心功能 |
|---|---|---|---|---|
| **BoringNotch** | 免费（开源） | 14 Sonoma | Swift（开源） | 音乐控制+可视化、文件暂存架（Shelf/AirDrop）、日历、HUD 替换（音量/亮度）、充电指示、手势自定义 |
| **Notchy** | 免费 | 13 Ventura+ | SwiftUI 原生 | 音乐、剪贴板历史、计时器（番茄钟）、AI 用量（Claude/Codex/Cursor）、命令面板、HUD、文件暂存；无刘海设备显示为**浮动胶囊（pill）** |
| **NotchNook** | $25 / $3月 | 14+ | Swift | 音乐、文件暂存、日历、HUD、AirPods |
| **Alcove** | $17 | 14+ | Swift | 音乐、HUD、日历、文件暂存 |
| **SuperIsland** | 免费开源 | 14+ | Swift | 媒体、电池、天气、日历、通知、文件暂存、股票、电脑状态（CPU/内存/温度/风扇）、**JS 扩展系统**（可安装第三方扩展） |
| **Atoll**（原 DynamicIsland） | 开源 | 14+ | Swift | 媒体、系统信息、快捷工具；基于 BoringNotch 演进 |
| **DynamicNotch** | 开源 | 14.6+ | Swift | 自研引擎：媒体、下载、AirDrop、计时器、录屏、连接事件、自定义 HUD；**无刘海设备自动切换为浮动胶囊（DynamicIslandShape）**，圆角过渡平滑 |
| **MediaMate / DynamicLake** | 付费 | 14+ | Swift | 音乐、HUD |

**共性设计模式**（可借鉴）：
1. **两种形态**：有刘海 → 包裹刘海；无刘海 → 顶部悬浮胶囊（pill）
2. **默认收起**：静止时极小（贴合硬件/贴近菜单栏），事件发生时展开，自动收起（BoringNotch 有 1–2s 自动最小化）
3. **功能优先级**：媒体控制是第一功能（几乎全部支持 Now Playing），其次是 HUD、文件暂存、日历
4. **队列化呈现**：DynamicNotch 用"queue-driven presentation"，多个事件排队依次展示
5. **性能要求**：空闲 CPU 接近 0%（Notchy 宣称 ~0.1%），动画 60fps

## 3. 对 DevNexus 灵动岛的适配建议（供决策）

### 3.1 现状问题（用户反馈）
- 媒体标题过长把胶囊撑满（已临时用 JS 截断 + 缩小按钮缓解）
- 窗口固定 256×48，无"紧凑/展开"两态

### 3.2 尺寸建议
| 状态 | 建议尺寸（逻辑像素） | 依据 |
|---|---|---|
| 收起（胶囊） | 宽 240–256 × 高 40–48 | iPhone compact 精神，贴合菜单栏/顶部 |
| 展开（媒体详情） | 宽 320–408 × 高 84–160 | iPhone expanded 84–160pt 区间，避开中间值 |
| 圆角 | 高度的一半（胶囊），展开用 20–24 | iPhone 44pt 比例（高 88→圆角 44） |

> 参考比例：iPhone 紧凑高 36.67 圆角 44 偏"药丸"，桌面端可用 高度/2 规则。

### 3.3 动画建议
- 尺寸/圆角/透明度用 **spring**：stiffness≈400、damping≈30（或 dampingRatio 0.8–0.85）
- 展开时长 ~300–500ms，内容用 scale+opacity 过渡
- 交互细节（可选）：展开瞬间轻微过冲回弹；收起时带一点"收进"的弹性
- 避免恒定 border-radius 生硬切换；如追求极致可上 squircle（结束动画后切 clipPath）

### 3.4 交互建议
- **点按** → 展开详情（当前点击无反应，应补上）
- **拖拽** → 移动窗口（已有，需保持）
- **滚轮** → 切换模块（已有）
- 展开态内嵌媒体控制按钮（已有，本次补上）

### 3.5 功能优先级建议
1. **媒体控制**（Now Playing：上一首/播放暂停/下一首 + 标题/播放器名）——已验证可用，做展开态
2. **时钟/日期**——保留收起态
3. **专注倒计时**——保留
4. 未来可加：系统 HUD、文件暂存、日历（参考 Mac 第三方）

### 3.6 关键技术点
- D-Bus MPRIS 读取：`ListNames` 返回 `as`（数组），必须用 `Vec<String>` 解析（本项目已修复）
- 命令必须 async + spawn_blocking，避免阻塞主线程（本项目已修复）
- 标题截断用 JS 侧控制字符数 + CSS ellipsis 双保险

## 4. 结论

- **两全其美的核心**：不要把"信息密度"硬塞进固定小胶囊，而是学 iPhone 做**两态**——收起态只放最核心（时间/播放状态图标），展开态（点按/长按）承载标题、播放器名、控制按钮等富内容，用 spring 动画平滑过渡。
- 参考 BoringNotch / Notchy / DynamicNotch：**无刘海设备也用顶部浮动胶囊**，静止极小、事件驱动展开、自动收起。
- 标题不再"抢空间"的根本解法 = 给内容一个更大的展开容器，而不是在 48px 高里挤。
